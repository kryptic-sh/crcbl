## Resolved findings

### Resume credentials

- **Single-use resume tokens:** successful reconnects rotate the resume token
  before sending `Accept`, so a token captured before one reconnect cannot
  resume the session after another disconnect.
- **Safe token equality:** `ResumeToken` keeps its bytes private and implements
  `PartialEq` with a full-byte comparison. Callers cannot accidentally select a
  timing-unsafe equality path.
- **Explicit protocol compatibility:** default client and server constructors
  reject placeholder identifiers outside unit tests. Networked embeddings must
  use constructors that accept explicit, non-zero engine build and schema
  identifiers.
- **Workspace-managed entropy dependency:** `getrandom` is declared in
  `[workspace.dependencies]`; `crcbl-server` inherits it with
  `{ workspace = true }`.
- **Session credential separation:** `ResumeToken([u8; 32])` is generated by the
  OS CSPRNG, remains separate from routing-only `SessionId`, redacts itself in
  `Debug`, and propagates entropy failures through fallible server constructors.
- **Protocol versioning:** protocol version 2 covers the incompatible `Hello`
  and `Accept` credential changes and cleanly rejects version 1 peers.
- **Injected reconnect timing:** server tick processing uses injected `Duration`
  state, allowing reconnect-grace expiry tests without wall-clock sleeps.
- **Safe snapshot construction:** `from_snapshot` validates snapshots;
  `from_trusted_snapshot` names the explicit validation opt-out.

### Delta replication

- **Lost ACK recovery:** `crcbl-client` re-ACKs its current baseline when a
  newer delta references an older baseline, allowing the server to resume from
  the client's state.
- **Entity lifecycle validation:** `DeltaCodec::apply` rejects adding an
  existing entity, modifying an absent entity, and removing an absent entity
  without mutating the baseline.
- **Component error classification:** oversized component data returns
  `BaselineDecodeError::ComponentTooLarge` rather than `DuplicateEntity`.
- **Roadmap accuracy:** P2b is marked in progress. Per-sector baseline streams,
  per-client rate limits, and CI fuzzing remain prerequisites for P2c.
